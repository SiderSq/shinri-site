Тест API поднимает реальный Express в отдельном временном каталоге. Тест браузера работает с собранным React, настоящим API и изолированными данными. Награды не подменяются моками.

### Проверенная проходимость

Вход с именем и кодом → экран внешнего снимка → проверка ключа → документы → расчёт **всех** токов и набора рабочих цепей → причинный порядок → интерпретация трёх измерений → выбор совместимого профиля, три основания и отдельное исключение каждой альтернативы → отчёт → перезагрузка с сохранённым серверным результатом.

Браузер дополнительно проверяет неверный набор цепей, раскрытие материалов, мобильные следы/суд и невалидный JSON в панели. Создаёт PNG и статические HTML для визуальной проверки в игнорируемом `test-results/archive`.

### Логика и защита

- Единственный совместимый профиль; ни одна улика отдельно не идентифицирует его.
- При удалении **каждой** из трёх улик появляется альтернатива.
- Неверная последовательность, неполное доказательство, неверные исключения не принимаются.
- Без входа нельзя восстановить данные; нельзя перескочить задания или сразу назвать убийцу.
- Сервер не принимает ID мини-игры как доказательство решения. Быстрые попытки получают 429.
- Legacy-выдача букв, проверка имени и старый сертификат получают 410, не обходят новый путь.
- Публичные ответы не содержат `traces[].value` или готового поля killer. Заключения выдаются только после подтверждённого анализа.
- Смена имён, порядка участников и добавление участников не требуют изменения движка.
- Невалидный раунд отклоняется до записи. Смена конфигурации обнуляет старую сессию/прогресс; logout делает токен недействительным.

## Чего эти проверки не доказывают

1. **Реальный Google Drive не проверен.** В репозитории нет ссылки и внешнего документа. Проверены интерфейс этапа, серверная проверка ключа и валидация HTTPS-ссылки в настройках. Нужна папка ведущего и ручное прохождение обычным аккаунтом.
2. Не проверены реальный хостинг/развёртывание, несколько серверных процессов и рестарт с сохранением сессий (сессии в памяти).
3. Исходное дело переведено в маркированную учебную реконструкцию. Дополнительные контрольные измерения и профили синтетические, а не факты о текущих игроках. Достоверность живых источников и условия владения подтверждает ведущий.
4. Ограничения попыток замедляют перебор. Абсолютная невозможность перебора конечных вариантов не заявляется; защита от простого угадывания имени обеспечена требованиями полного доказательства.
5. Исторический suite сохранён как `test:legacy`, но не объявлен успешно пройденным: он проверяет намеренно отключённые контракты и старую игровую механику. Новая версия покрыта отдельным suite без skipped тестов.
6. Старые демонстрационные пароли/ответы остаются в истории публичного репозитория. Для живой игры нужны новые секреты и приватный SHINRI_DATA_DIR. Убран fallback-пароль администратора; требуется ADMIN_PASSWORD.
