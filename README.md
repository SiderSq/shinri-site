# Shinri Trial / Цена надежды

Неофициальный RP-терминал Нагито Комаэды для Garry’s Mod. Цепочка: **вход → ключ из Google Drive → восстановление архива → исследование → доказательный вердикт**.

## Запуск

Требуется Node.js 22+ (Vite 8). На Node.js 24 проверено.

```sh
npm ci
npm ci --prefix client
npm run build --prefix client
# Задайте ADMIN_PASSWORD в .env: известный старый пароль больше не используется.
npm start
```

Сайт: `http://localhost:3000`. Панель ведущего: `/admin`; настройки нового раунда: `/admin/round`. Пароль администратора обязателен через `ADMIN_PASSWORD`. Не публикуйте `.env`, коды и решения живого раунда в GitHub.

## Приборная лаборатория v2 — текущий путь

В текущем `main` дело не содержит `archiveRound`; игрок использует обычный терминал и пять приборов по три этапа. Сервер подтверждает настройки и вывод каждого этапа; фрагмент имени появляется только после трёх проверок. Подробности, ограничения миграции, A/B-аудио и тесты: [LAB_V2_NOTES.md](LAB_V2_NOTES.md).

После сборки `/audio-preview` позволяет сравнить отдельные реальные звуковые рецепты. Автономное [аудиодемо](docs/audio-comparison.html) нужно скачать и открыть в браузере: оно содержит обе записи и не требует входа в Notion.

## Архивный сценарий — сохранённая альтернативная реализация

**Следующий раздел описывает архивный режим, а не работающую конфигурацию текущего дела.** В текущем `server/data/case.json` отсутствует `archiveRound`; архивные тесты уже не проходили на исходном `main`. Эта доработка не включает восстановление архивного сценария.

### Подготовка архивного раунда

1. Начальная `archiveRound` в `server/data/case.json` — **учебная реконструкция** инцидента в мусоросжигателе. Все новые контрольные измерения и профили являются учебными, не фактами о живых игроках.
2. В `/admin/round` загрузите/измените JSON: участники, их личные ведомости, измерения, причинные связи, текст дела, условия атрибуции, материалы. Подробно: [руководство ведущего](ROUND_GUIDE.md).
3. Создайте документ «Снимок 04-271» в Google Drive, разместите там ключ, совпадающий с `recoveryKey` из параметров дела. Задайте `driveUrl` и права просмотра. **В исходном репозитории ссылки нет**: реальный Drive не подключён автоматически. Пароль — ключ внутри документа, не нативная парольная защита папки Drive.
4. Для живого раунда укажите `mode: "live"`, `confirmed: true`, новую `id` и действительную ссылку Drive. Это подтверждение ведущего, а не автоматическая проверка реальных событий. Не заменяйте учебные имена на игроков без сбора фактов.
5. Нажмите «Проверить и опубликовать». Неоднозначный/непроходимый структурно сценарий не сохраняется. Изменение конфигурации или кодов обнуляет старый прогресс при следующем обращении игрока.
6. Самостоятельно пройдите внешнюю папку с правами обычного игрока. Доступность и содержимое Drive сайт не проверяет.

Для производства используйте **приватное хранилище вне репозитория**: скопируйте учебный `case.json` в отдельный каталог и задайте `SHINRI_DATA_DIR` на этот каталог. Сервер хранит там case/locks/audit; клиент не имеет доступа к файлам каталога. Хостинг должен иметь постоянный диск. Прогресс сессий пока в памяти: после перезапуска сервера игрок проходит вход и задания заново.

## Игровая механика

- Цепь: расчёты токов + полный набор рабочих измерений; открытая цепь и перегоревший предохранитель дают ноль.
- Хронология: восстановление единственной причинной цепи, доступное мышью и клавиатурой.
- Следы: спектр, микрорельеф, поправка часов; условия автоматически генерируются из измерений, сервер сверяет скрытые выводы с ними.
- Суд: один совместимый профиль, три основания и конкретное противоречие для **каждого** другого участника. Простое имя не принимается.
- Любая одна улика оставляет несколько кандидатов; удаление любой из трёх тоже оставляет альтернативу. Вердикт не сводится к одному случайному совпадению.
- Неверный ответ даёт направление проверки, но не раскрывает правильный выбор. Ограничения: не чаще 1 проверки за 1,2 секунды, максимум 12 за минуту на сессию. Это защита от быстрого перебора, не обещание полной невозможности перебора конечных вариантов.

При активном `archiveRound` старые игровые API возвращают **410** (кроме status/round-time). В частности, отключены выдача букв по ID мини-игры, старый ввод имени и обход через сертификат. Старые компоненты оставлены в репозитории для миграции, но не входят в новый путь игрока. Старая панель редактирует legacy-поля; для нового дела используйте `/admin/round`.

## Проверки

```sh
npm run test:lab         # текущая приборная лаборатория: модели и реальный API
npm run test:design      # текущий интерфейс, реальный сервер, 320/390/1440, аудио
npm test                 # исторический archive suite; сейчас не проходит без archiveRound
npm run test:strict      # тот же исторический archive suite
npm run build --prefix client
# Один раз: npx playwright install chromium (или задайте CHROMIUM_PATH)
npm run test:ui          # реальный браузер, изолированный сервер, снимки в test-results/archive
npm run test:legacy      # исторические требования, несовместимы с активным archiveRound
```

API-тесты используют отдельный временный каталог; рабочее дело/аудит не меняют. Отчёт о выполненных проверках: [QA_REPORT.md](QA_REPORT.md).

**Безопасность:** прежние демонстрационные коды уже были опубликованы в истории репозитория. Считайте их известными, замените в производственном приватном хранилище. Новая версия убирает известный fallback-пароль администратора и вывод кодов в консоль; это не стирает старую Git-историю.
