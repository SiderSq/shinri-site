# Руководство ведущего / один движок, разные раунды

## Разделение данных и заданий

`archiveRound` — сценарий. Компоненты и проверки не используют имена, таланты, конкретного убийцу или алиби. Меняются только данные; механика остаётся: электрический анализ → причинный порядок → независимые следы → исключение альтернатив.

Учебный сюжет сохраняет двухходовую ловушку, стяжки, короткий разговор, перенос капкана помощником и уборку. Для другого раунда можно сменить текст/источники/названия событий и измерения. Электрическая, спектральная и микрорельефная лаборатории — устойчивые типы заданий: если они не существуют в реальном сюжете, оставьте их как явно маркированную архивную тренировку, **не** выдавайте их за живые улики.

## Поля

- `id`: новый уникальный код раунда; `mode`: `archive` или `live`.
- `title`, `brief`: введение; `exhibits`: массив `{id,title,content,image?}`. Изображения локальные `/uploads/...` или доверенные HTTPS URL. Не помещайте ключи/решения в публичные материалы.
- `driveUrl`: `https://drive.google.com/...`; `driveInstructions`: как игрок найдёт внешний документ. Редактирование ключа восстановления — в параметрах дела `/admin` (`recoveryKey`), не в JSON раунда.
- `circuit.threshold`: минимальный ток, А. `rows`: уникальные `{id,voltage,resistance,closed,fuse}`. Нужны рабочие и нерабочие строки. Требуется расчёт всех токов; разрыв и неисправный предохранитель дают 0. Числовые ответы допускают погрешность 0,01 А.
- `events`: 4–8 `{id,text}` в стартовом порядке; `edges`: `[раньше,позже]`. Требуется ровно один топологический порядок. `chronologySource` должен сообщать **все** необходимые связи понятным игроку текстом. Проверка графа не способна проверить правдивость свободного текста — это ответственность ведущего.
- `participants`: 4–30 `{id,name,profile}`. ID стабильны, не зависят от имени. `profile` содержит значения по ключам трёх следов, например `contact`, `tool`, `window`. Это ведомости подтверждённого личного владения, не обвинительные ярлыки.
- `traces`: ровно три `{id,key,title,provenance,kind,measurement,options,value}`. `value` — серверный вывод, не отправляется игрокам. Он обязан совпадать с результатом измерения; `options` включают значения всех профилей.
- `attribution`: почему эти три следа принадлежат одному исполнителю, что исключает передачу/подброс/соучастие. В `live` дополнительно нужны `confirmed: true` и Drive-ссылка.

### Варианты измерений

```json
{"kind":"spectrum","measurement":{"sample":580,"bands":[{"name":"Медь","min":570,"max":590},{"name":"Сталь","min":430,"max":450},{"name":"Алюминий","min":390,"max":410}]}}
```

Должен остаться ровно один диапазон, содержащий sample, включая границы.

```json
{"kind":"tool","measurement":{"marks":[0.4,0.8,1.2],"tools":[{"name":"Лезвие A","step":0.4},{"name":"Лезвие B","step":0.6},{"name":"Лезвие C","step":0.8}]}}
```

Каждая соседняя разность должна совпадать с шагом одного эталона. Не путайте координату и разность.

```json
{"kind":"clock","measurement":{"interval":["21:45","21:47"],"fastByMinutes":3}}
```

Положительная поправка = часы спешат: вычесть. Отрицательная = отстают: прибавить. Поддерживается интервал внутри одних суток; пересечение полуночи пока отвергается, а не рассчитывается неправильно. Значение и варианты интервала используют знак `–`.

Условия для игрока генерируются автоматически из `measurement`: нельзя отдельно отредактировать видимое число, оставив прежний скрытый ответ.

## Логическая состоятельность

Публикация проверяет:
1. Все профили/ID и измерения валидны.
2. Причинный граф не цикличен и имеет ровно один порядок.
3. Пересечение трёх условий даёт одного человека.
4. Ни одна улика отдельно не раскрывает его.
5. Без любой одной из трёх улик остаётся другой кандидат.

Начальная матрица удовлетворяет этому: один альтернативный профиль отличается материалом, другой инструментом, третий временем. Это учебная структура, а не универсальное доказательство виновности. Совпадение карточки/предмета/уборки не означает убийство без подтверждённой связи с действиями исполнителя.

Чтобы сменить убийцу, перенесите совместимый набор признаков к нужному ID и перераспределите отличия остальных; не редактируйте код или имя-ответ. Проверьте, что имена и признаки взяты из текущего раунда. При большем составе добавляйте несовместимые профили; суд потребует отдельного исключения каждого.

## Перед стартом живой игры

- [ ] Факты действительно получены в текущем раунде; учебные записи удалены/маркированы.
- [ ] Непрерывное личное владение/непередача предметов подтверждены. Если нет — не публикуйте вывод о виновности по этой матрице.
- [ ] Свободный текст совпадает с графом, приборами и профилями; нет противоречащих старых документов.
- [ ] Новый ID, новые коды, уникальный ADMIN_PASSWORD; секреты в приватном SHINRI_DATA_DIR.
- [ ] Drive открыт аккаунту игрока; документ содержит правильный recoveryKey. Проверьте вручную не как владелец папки.
- [ ] Пройден весь путь обычным игроком, а не администратором.

### Ограничения

Настройка сейчас через JSON с серверной валидацией, не визуальный drag-and-drop редактор. Сессии в памяти. Проверки не удостоверяют реальные события Garry’s Mod или достоверность показаний. Конечные задания теоретически можно перебирать; сайт предотвращает быстрые попытки и требует полного доказательства вместо одного имени.
