# Приборная лаборатория v2 и выразительная звуковая палитра

## Что переработано

Это новый проход после предыдущей доработки, а не повторная настройка громкости. Материалы дела и личности персонажей не изменены. Все дополнительные наблюдения обозначены как учебные модели приборов, а не новые доказательства сюжета.

### Пять приборов, пятнадцать этапов

| Прибор | Освоение | Помехи | Комплексная экспертиза |
|---|---|---|---|
| Электроцепь | Стыковка портов и расчёт I = U / R | Больше узлов и повреждённая ветвь | Сетка 3×3, обход повреждений, другая нагрузка |
| Спектрометр | Реагент, УФ-лампа, сканирование и отрицательный контроль | Калибровка нуля по контрольной линии | Отсев похожего пика по отношению сигналов |
| Хронология | Три причинно связанных события | Пять событий | Шесть событий и поправка часов одного источника |
| Механизм | Безопасная разгрузка пружины | Штифт извлекается после разгрузки; раскрытие меняет усилие | Дополнительный демпфер в модели нагрузки |
| Микрорельеф | Выбор рисунка борозд и совмещение угла | Смещение и фокус влияют на оценку | Требуется сравнить оба участка образца |

Управление остаётся простым: нажатие, стрелки перестановки, числовые поля, кнопки ± и ползунки. Нет обязательного таймера, перетаскивания или проверки реакции. Последовательные этапы подтверждаются на сервере; неудачная проверка сохраняет настройки на экране.

### Композиция и доступность

- На компьютере — навигационная рейка приборов и один рабочий стол: наблюдение слева, критерии и регуляторы справа. На телефоне рейка заменена подписанным select; зоны складываются вертикально.
- Технический стиль сохранён в схемах и числах; основной текст — Golos Text, измерения — JetBrains Mono. Убраны сплошной капс и избыточные вложенные панели внутри новой лаборатории.
- Палитра лаборатории: `#07080D` фон, `#111727` поверхности, `#EDF3FC` текст, `#65E2EC` активный прибор, `#FF398F` сюжетный акцент, `#FFC45E` предупреждение; зелёный `#83E4B5` означает подтверждение. Основная кнопка анализа — циановая, розовый не используется для каждой операции.
- Состояние передаётся не только цветом: статус контура, повреждённые узлы с крестом/пунктиром, текст измерений, метки этапов. Есть числовое описание борозд для невизуального сравнения.
- Кнопки касания не меньше 44×44 px, видимый фокус, сохранение фокуса при перестановке событий, статус/ошибки для скринридера. Форма связана с текстом ошибки. Ссылка быстрого перехода скрыта до фокуса, а не просто сдвинута за экран.
- Движение раскрытия механизма отвечает на действие пользователя и учитывает системный `prefers-reduced-motion`. Новый режим «Без эффектов» не добавлен; существующий переключатель CRT сохранён.

### Звук: реальные разные фактуры

- Навигация: короткий восходящий цифровой переход.
- Поворот: три шумовых механических щелчка с низким телом вместо одиночного похожего бипа.
- Сканирование: проход по частоте, воздушная шумовая фактура и фиксация результата.
- Штифт: низкий контакт и отдельный щелчок освобождения.
- Сравнение: два тактильных отсчёта.
- Этап: восходящая фраза; завершение прибора — более длинный тёплый аккорд с обертонами.
- Ошибка: короткий приглушённый нисходящий удар без резкого высокого свиста.
- Финал: низкая опора, аккорд и короткое сияющее завершение.

Повторяющиеся операции имеют три варианта шумовой фактуры/тона. Сохранены ограничение частоты/полифонии, выключение звука, настройка громкости и остановка при скрытии вкладки. Нет автоматического запуска до первого жеста. Обратная связь полностью читается и без звука.

На `/audio-preview` сравниваются отдельные старые и новые рецепты Web Audio, не подменённые записи. В `docs/audio-comparison.html` встроены две MP3-записи по 15 секунд (навигировать, повернуть, сканировать, ошибка, успех, финал). HTML надо скачать из GitHub и открыть в браузере; вход в Notion не нужен. Проигрывание одной записи останавливает другую. Уровень шины одинаковый — 60%; это не нормализация воспринимаемой громкости.

Автоматические измерения подтверждают изменение спектра, а не только усиления: центроид механического сигнала примерно 533 → 2208 Гц, сканирования 628 → 2462 Гц в этих контрольных записях. Это дескриптор тембра, не оценка приятности. Субъективное качество требуется проверить прослушиванием на телефоне и в наушниках; оно не считается доказанным по графикам.

## Сервер и миграция

- Новый API `/api/investigation/lab/workstation` + `/submit-analysis` проверяет текущий этап, версию сессии, реальные численные условия и вывод, а не один ID мини-игры.
- Старый `/lab/solve-minigame` больше не выдаёт награды. Финальный `/verify-killer` требует пяти подтверждённых анализов. Это проверка конкретного пути, не полный аудит всех legacy API.
- Версия задания — случайный непрозрачный nonce. Приватный fingerprint дела не выдаётся клиенту. Изменение значимых полей дела сбрасывает лабораторию.
- Не чаще одной проверки за 800 мс, максимум 12 **неудачных** проверок за минуту; при 429 показано время ожидания. Успешные этапы не расходуют лимит ошибок.
- Старые флаги успешности из localStorage не импортируются как доказательство: пользователям надо пройти новые этапы. LocalStorage только отражает серверное состояние для существующей реконструкции имени.
- Прогресс остаётся в памяти серверной сессии. Перезапуск сервера/повторный вход сбрасывает этапы; постоянное хранилище пока не реализовано.
- При активном `archiveRound` этот приборный API отключён (410). Работа над альтернативным архивным сценарием не входит в эту доработку.

## Проверки

Проверено на Node.js 24 и локальном Chromium:

- `npm run test:lab`: **25/25**, включая 15 этапов с несколькими seed, порты/повреждения, численные границы, калибровку, дубликаты, штифт, два окна микроскопа, реальный HTTP-путь до наград и вердикта.
- `npm run test:design`: реальный изолированный Express + собранный React. Все 15 этапов сняты на 320/390/1440 px; награды не замоканы. Проверены вращение клавиатурой, фокус перестановки, сканирование, штифт, сравнение двух окон, ошибка, сертификаты и A/B-плеер. Проверены остановка активных голосов при mute/скрытии вкладки и ограничение частых повторов. Нет ошибок страницы/горизонтального переполнения в проверенных состояниях.
- 60 аудиорендеров (20 событий × 3 варианта): конечные значения, не пустые сигналы, пиковые значения ниже 0,85 при громкости 60%. Это технический контроль, не полная проверка воспринимаемой громкости.
- Сборка проходит; остаётся предупреждение Vite о JS-чанке >500 kB.
- Целевая проверка oxlint новых/изменённых файлов: 0 ошибок, 1 предупреждение `set-state-in-effect` для загрузки лаборатории через эффект. Полный исторический lint проекта не объявляется чистым.
- Исторический `npm test` для archive: **17 ошибок**. На исходном main он тоже имел 17 ошибок: конфигурация дела не содержит ожидаемого `archiveRound`. Этот suite не заменён, не скрыт и не объявлен пройденным.

Снимки находятся в локальном `test-results/design-v2` после запуска теста. Представительные состояния отдельно просмотрены; поправлены стыки схемы, мобильные кнопки, перенос счётчика и текст навигационной рейки.

## Сборка перед публикацией

Сгенерированный `client/dist` не включается в этот исходный PR. После слияния **обязательно**:

```sh
npm ci
npm ci --prefix client
npm run build --prefix client
npm run test:lab
npm run test:design
npm start
```

Если просто перенести исходники, не пересобирая `client/dist`, сервер продолжит показывать старый сайт. Эта работа не включает слияние PR или выкладку на хостинг.

## Идеи, пока не реализованные

1. **P1 — постоянный прогресс с миграцией сессий.** Убрать потерю пятнадцати этапов после рестарта; хранить версию задания и результаты на сервере в БД.
2. **P1 — распространить типографику лаборатории на документы и фотоархив.** Технический моноширинный шрифт оставить для метаданных, основной текст 16–18 px; унифицировать плотность панелей и действия. Это уменьшит визуальный разрыв между разделами.
3. **P1 — настройка моделей ведущим.** Редактируемые наблюдения/сложность вместо учебного генератора; требуются подтверждённые материалы раунда и тест однозначности. Не подменять сюжетные факты произвольными числами.
4. **P2 — иллюстрации вместо условных схем.** Общий язык криминалистических чертежей, увеличиваемые детали улик; нужны оригинальные ассеты или согласованный источник с лицензией.
5. **P2 — прослушивание и настройка на реальных устройствах.** A/B-оценка неприятности/различимости на динамике телефона и в наушниках; при необходимости скорректировать громкость групп событий, добавить отдельную громкость фона. Автоматические аудиометрии этого не заменяют.
6. **P2 — отложенная загрузка приборов и аудиодемо.** Снизить большой JS-чанк и время первого открытия на мобильной сети.
7. **P3 — тонкая реактивная подсветка CRT только вокруг приборных схем.** Не накладывать шум поверх документов; не добавлять новый режим «Без эффектов».
